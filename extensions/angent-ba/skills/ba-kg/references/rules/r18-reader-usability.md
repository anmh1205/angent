# R18: Audience-focused usable artifact

## Operational contract

Choose a document structure that answers the reader's decisions in a natural order: context and problem, accepted requirements or implementation, evidence, exceptions, impact and next decision. Avoid a giant collection of unrelated checklist bullets.

## Checks before accepting an artifact

Use unambiguous terminology, consistent actor names and quantitative units. In Vietnamese, prefer natural professional terms; translate or define imported English technical words when needed.

## Failure response

For visual assets verify actual legibility, keyboard access, contrast, viewport overflow and link correctness. The diagram's successful compile is not proof stakeholders can read it.

## Grounded example

An SRS must allow an engineer and tester to derive the same behavior; a stakeholder preview must lead back to each claim's source instead of displaying unexplained IDs.

**Evidence boundary:** specialist advice does not establish completed provider writes or approve business requirements. The actual source and observed result remain decisive; ANGENT Root and Quality retain oversight.
