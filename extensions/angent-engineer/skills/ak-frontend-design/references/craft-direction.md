# Frontend craft and aesthetic direction

The purpose is to prevent generic interface mode-collapse while preserving product usability.

## Derive a thesis

Before styling, be able to state:
- content/user job;
- intended perception;
- primary visual hierarchy;
- design-system lineage (existing/reference/new);
- one memorable element or compositional idea.

If the direction can be swapped into an unrelated competitor by changing the logo, it is probably too generic.

## Prefer composition over decoration

Question:
- repeated equal cards;
- decorative eyebrow/status labels;
- arbitrary gradients/glass/shadows;
- oversized rounded surfaces without semantic reason;
- technical/monospace styling used only as costume;
- repetitive centered sections.

These are warnings, not universal bans. Existing brand/system or content structure can justify them.

## Typography and color

Use type roles intentionally: display, body, UI/data.

Preserve readable body text and enough contrast. Build a coherent neutral/accent system rather than distributing saturated color everywhere.

Do not introduce a font/palette merely because it is fashionable.

## Layout and rhythm

Vary layout only when content relationships differ.

Maintain a spacing/grid system, but do not make every section geometrically identical.

At responsive breakpoints, preserve priority and task flow; recomposition is often better than uniform shrinkage.

## Motion

Motion should explain state, hierarchy or spatial relation.

Avoid animation that delays content or becomes required for comprehension. Provide reduced-motion behavior.

## Rendered self-review

Check:
- hierarchy/squint test;
- removable-decoration/delete test;
- brand/topic specificity;
- real content density;
- overflow and long text;
- mobile viewport;
- keyboard/focus;
- contrast;
- motion/reduced motion;
- consistent radius/depth/token systems.

When several failures trace to a timid/generic direction, revisit the visual thesis instead of patching each symptom.
