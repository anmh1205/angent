# UI states and responsive behavior

For each flow/component consider:
- default;
- hover/focus/active;
- disabled;
- loading/skeleton;
- empty;
- error;
- success;
- permission/auth;
- overflow/long content;
- mobile/tablet/desktop;
- reduced motion;
- keyboard navigation.

Responsive design may change hierarchy/navigation, not only column count.

Define behavior at breakpoints based on content/task constraints rather than device labels alone.
