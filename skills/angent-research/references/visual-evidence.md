# Visual evidence — source, identity and reuse

Visual collection is research into a specific explanatory or evidentiary need. Do not search a broad topical noun and accept the first plausible-looking photograph.

## Find the image that answers the question

Specify the observable feature first: which connector, board revision, UI state, plotted quantity, measured waveform, mechanical part, or physical relationship the reader needs to recognize. Prefer original technical manuals, manufacturer documentation, primary project repositories, official reference diagrams and authenticated captures over stock imagery or visually similar search results.

Match the exact model, revision, firmware/software version, orientation and relevant configuration when these can change the depicted feature. A photograph of the same product family is not evidence for the user's specific pinout or interface. For abstract mechanisms, a verified original diagram may be more precise than a product photo.

Inspect the candidate rather than trusting the search caption. Confirm that the referenced feature is actually visible and readable, that labels and cropping preserve meaning, and that perspective or diagram conventions cannot change the intended conclusion. For diagrams, verify arrows, boundaries and legend semantics against primary sources.

## Evidence, generated explanations and permissions

Distinguish:
- **captured evidence**: an actual screenshot, instrument capture, photo or measured plot, with its source and observation conditions;
- **adapted figure**: derived from an identified source, clearly attributed, with modifications noted when material;
- **original explanatory drawing**: synthesized from verified facts, explicitly not represented as a physical capture or measurement.

Record enough provenance to revalidate the asset: source URL or repository and file path, owner, revision/date, exact subject, relevant license/usage permissions and any uncertainty. Public accessibility does not establish a right to redistribute. If permission is unclear, prefer a source link, a properly authorized screenshot, or an original abstraction built only from non-protected facts.

Never use an image from a different board, connector, operating system state or software version merely because it looks attractive. If the correct image cannot be sourced, say what remains unverified and ask Authoring to choose a different representation or defer the figure.

## Hand off only decision-relevant evidence

Supply Authoring with the figure's explanatory job, verified identity, what the reader should inspect, known limitations and attribution. Supply Format with the actual asset/URL and any cropping, caption, alt-text or destination rendering constraints. Format checks the final figure after publication; Research cannot certify a visual it has not inspected.

A visual is useful only if it reduces the reconstruction effort or uncertainty for the target relation. More images are not intrinsically better.
