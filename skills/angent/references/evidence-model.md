# Evidence model — collect what changes the decision

Research organizes evidence around active claims and uncertainty.

## Source roles

Classify a source by what it can establish:

- **normative** — standard, schema, law, protocol or authoritative requirement;
- **primary implementation** — source code, official implementation, canonical repository;
- **vendor specification** — product/platform contract and supported behavior;
- **observed runtime evidence** — logs, measurements, provider state, screenshots, traces;
- **independent analysis** — external synthesis or evaluation;
- **community experience** — useful operational signal, not authoritative by default;
- **illustrative** — helps understanding but does not establish the claim.

Authority is claim-specific. A primary implementation may establish current behavior while a normative specification establishes what behavior is required.

## Evidence item

For material claims record:
- claim/question;
- source and source role;
- version/platform/time boundary;
- direct observation/fact;
- interpretation;
- confidence/limitations;
- conflict with other evidence;
- effect on the current hypothesis or decision.

## Information value

Prefer evidence that discriminates live alternatives. Ten sources repeating the same non-decisive fact may add less value than one authoritative observation that separates two hypotheses.

## Conflict handling

Do not average contradictions. Check:
- different versions;
- different platforms/configurations;
- normative versus implementation behavior;
- stale documentation;
- observation quality;
- scope mismatch.

Return unresolved conflicts to Reasoning when they can change the decision.

## Visual evidence

For screenshots, photos, diagrams and traces, preserve exact identity, version/state and what relation the visual proves. Visual relevance by topic is not provenance.
