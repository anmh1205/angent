# Hypothesis reasoning — preserve alternatives until evidence separates them

Use explicit hypotheses when multiple mechanisms can plausibly explain a material observation.

## Hypothesis record

For each live hypothesis keep only what helps discriminate it:

- **claim** — proposed mechanism/explanation;
- **prior support** — why it remains plausible from current evidence;
- **prediction** — what should be observed if it is true;
- **discriminator** — observation/test that separates it from alternatives;
- **status** — live, weakened, rejected, confirmed-enough-for-current-decision;
- **residual uncertainty** — what still cannot be concluded.

## Competing explanations

Do not generate alternatives merely for symmetry. Maintain credible alternatives that would change diagnosis, design or action.

## Evidence update

A useful evidence item changes at least one hypothesis:

```text
observation → support / weaken / reject / leave-undistinguished
```

"No result" can still be informative if the test had a clear expected observation.

## Avoid premature collapse

Do not:
- convert a common cause into certainty without discriminating evidence;
- keep a rejected hypothesis alive because it is familiar;
- treat tool chronology as causal proof;
- hide unresolved ambiguity in confident wording.

## Falsification

For consequential reasoning, ask what observation would make the preferred explanation wrong. If no such observation can be stated, the hypothesis may be too vague to guide action.

## Exit condition

Stop expanding the hypothesis set when the current decision can be made robustly despite remaining uncertainty.
